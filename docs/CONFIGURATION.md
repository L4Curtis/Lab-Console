# Configuration reference

**English** · the descriptions are those of `.env.example`; [README.fr.md](../README.fr.md) explains the main settings in French.

> Generated from `.env.example` by `npm run gen-config-doc`. Do not edit this file:
> change the comments in `.env.example` and generate it again.

Settings are environment variables, read from `.env` (Docker Compose passes it
to the container). A variable shown as *(optional)* is commented out in
`.env.example`; the value is the default or an example. The jump server, console
login and allowed consoles can also be changed from Administration > Lab
parameters without a restart.

## Web server

| Variable | Default / example | Description |
|---|---|---|
| `PORT` | `3000` | Port and address the server listens on (inside Docker, Compose maps PORT on the host) |
| `HOST` | `0.0.0.0` | Part of the group described in the row above. |
| `PUBLIC_URL` | *(empty)* | Public address of the platform, as users type it: scheme and host, no path. Required: sign-in redirects and cookie security derive from it (https gives the session cookie the __Host- prefix and Secure) |
| `TRUSTED_PROXIES` | *(empty)* | Reverse proxies (nginx, Traefik, a CDN…) whose X-Forwarded-For header is believed: comma list of IP addresses and CIDR blocks, IPv4 or IPv6. List EVERY hop in front of Lab Console: behind NPM and then Cloudflare, NPM's address AND Cloudflare's published ranges (see docs/v2/AUTH.md). Everyone else's header is ignored, so nobody can fake their address. Empty = the platform is reached directly. e.g. 192.168.10.112,172.16.0.0/12 (The upstream TRUST_PROXY=true is refused at start-up: remove it.) |
| `ALLOWED_ORIGINS` | *(empty)* | Other origins (scheme://host[:port], comma list) from which browsers may open the WebSockets and send changes, besides PUBLIC_URL: needed when the site is also reached under another address (a proxy, a second name). Empty = PUBLIC_URL only. |
| `DEFAULT_LOCALE` | `fr` | Language of the interface on a first visit: fr or en. Each user can switch; the choice is remembered in their browser |
| `DIAGRAM_PATH` | `./diagrams/diagram.drawio` | The diagram shipped with the platform. On the first start it is copied to DATA_DIR/diagrams/current.drawio, which is the active diagram from then on (replace it from Administration > Diagram, with versions and rollback) |
| `DATA_DIR` *(optional)* | `./data` | Where the platform keeps its state. The only directory it writes to; must be writable by the service account. Default ./data; the Docker image sets /data and expects a volume there. It holds the database lab-console.db (sessions, audit trail, settings, teams, the index of jobs and snapshots, the script library, device notes, bench chat…; SQLite, with its -wal and -shm files, mode 600) and the documents people download: configuration snapshots and TP templates, console journals, diagram versions. On the first start after an upgrade, the JSON / JSONL files of before (auth/*.json, audit/*.jsonl) are imported into the database and renamed *.imported, never deleted. Back it up service stopped, or with sqlite3's .backup while it runs. Needs Node.js 22.13 or later (built-in SQLite) |

## Sign-in (see docs/v2/AUTH.md)

| Variable | Default / example | Description |
|---|---|---|
| `LOCAL_ADMIN_USERNAME` | *(empty)* | There is no way to run without sign-in. The local administrator is mandatory: the platform refuses to start without these three lines. Generate them with: npm run setup-admin (password typed without echo) It is the emergency account: user name + password + a 6-digit code from an authenticator app, and it works when the identity provider is down |
| `LOCAL_ADMIN_PASSWORD_HASH` | *(empty)* | Part of the group described in the row above. |
| `LOCAL_ADMIN_TOTP_SECRET` | *(empty)* | Part of the group described in the row above. |
| `OIDC_ISSUER` | *(empty)* | OpenID Connect (optional): what students and teachers sign in with. Any standard provider: Pocket ID, Authentik, Keycloak, Authelia… Register a client with the callback URL ${PUBLIC_URL}/auth/callback Leave OIDC_ISSUER empty to use the local administrator only |
| `OIDC_CLIENT_ID` | *(empty)* | Part of the group described in the row above. |
| `OIDC_CLIENT_SECRET` | *(empty)* | Empty = a public client (PKCE only). With a secret, how it is sent: client_secret_basic (default) or client_secret_post |
| `OIDC_CLIENT_AUTH_METHOD` *(optional)* | `client_secret_basic` | Part of the group described in the row above. |
| `OIDC_SCOPES` | `openid profile email groups` | Part of the group described in the row above. |
| `OIDC_GROUPS_CLAIM` | `groups` | Where the provider puts the groups: a claim name or a dotted path (Keycloak: realm_access.roles). An array or a single string; looked up in the ID token first, then at the userinfo endpoint |
| `OIDC_ADMIN_GROUPS` | *(empty)* | Members of these groups are administrators; everyone else is a student |
| `OIDC_ALLOWED_GROUPS` | *(empty)* | Empty = every account of the provider may sign in. Otherwise, only members of these groups (and of OIDC_ADMIN_GROUPS) |
| `OIDC_PROVIDER_NAME` | `SSO` | Label of the sign-in button ("Sign in with …") |
| `OIDC_ALLOW_INSECURE` *(optional)* | `false` | Plain-http issuers are refused except on localhost. true accepts one on a test bench (the mock provider of dev/mock-oidc.js); never with real accounts |
| `APP_SECRET` *(optional)* | *(empty)* | Encrypts the secrets saved from the administration pages: the SSO client secret ("Sign-in (SSO)" page) and the lab parameters' passwords and key ("Lab parameters" page), both kept in the database (DATA_DIR/lab-console.db). Optional: without it they are stored in clear in files only the service can read. At least 32 characters: openssl rand -base64 48 Changing or removing it makes the saved secret unreadable: set it again. |

## Credential set 1: SSH jump server

| Variable | Default / example | Description |
|---|---|---|
| `SSH_HOST` | `<IP_ADDRESS>` | The SSH_*, TELNET_*, ALLOWED_CONSOLE_HOSTS and ALLOWED_PORT_RANGE values are the starting point: Administration > Lab parameters can replace them without a restart (saved in the database, secrets encrypted with APP_SECRET when it is set) |
| `SSH_PORT` | `<SSH_PORT>` | Part of the group described in the row above. |
| `SSH_USERNAME` | `<USERNAME>` | Part of the group described in the row above. |
| `SSH_PASSWORD` | `<PASSWORD>` | Part of the group described in the row above. |
| `SSH_HOST_FINGERPRINT` | *(empty)* | Pin the jump server's host key: required in production (NODE_ENV=production, the Docker image), where no console connects without it (or the one saved on the lab page) Get it with: ssh-keyscan -t ed25519 <IP_ADDRESS> \| ssh-keygen -lf - |
| `SSH_PRIVATE_KEY_PATH` *(optional)* | `./keys/id_ed25519` | Optional: key authentication instead of SSH_PASSWORD |
| `SSH_KEY_PASSPHRASE` *(optional)* | *(empty)* | Part of the group described in the row above. |
| `PROXMOX_TUNNEL_TRANSPORT` *(optional)* | `auto` | How the Proxmox tunnel crosses the jump server (device consoles are unaffected): auto - use TCP forwarding; if the jump server forbids it ("open failed" / administratively prohibited), fall back to a relay command. Default. forward - TCP forwarding only (needs AllowTcpForwarding on the jump server) exec - always run a relay command (socat/nc/bash), like the consoles do |
| `PROXMOX_TUNNEL_RELAY` *(optional)* | `socat - TCP:{host}:{port}` | Optional explicit relay for exec/auto, with {host}/{port}. Empty = auto-detect (prefers socat, then ncat, nc, then bash /dev/tcp). |

## Bench jobs (backup, injection, reset)

| Variable | Default / example | Description |
|---|---|---|
| `JOB_DEVICES_AT_ONCE` | `5` | Devices one job works on at the same time (one console line each) |
| `JOB_COUNTDOWN_SECONDS` | `10` | A reset starts this many seconds after it is confirmed; anyone watching may cancel it meanwhile |
| `JOB_IMPORT_MAX_KB` | `2048` | Largest ZIP accepted when a snapshot or a TP template is imported (KB) |
| `JOB_TIME_SCALE` | `1` | The device driver's waiting budgets are multiplied by this. Keep 1 on the real lab (a reload may take fifteen minutes); the simulator boots in seconds, so a demonstration on the mock lab may use 0.05 |

## Limits

| Variable | Default / example | Description |
|---|---|---|
| `MAX_SESSIONS` | `40` | Console lines open on the platform at once (several people on one line count once) |
| `MAX_SESSIONS_PER_CLIENT` | `6` | Consoles one signed-in user may have open at once (per user, whatever their address) |
| `IDLE_TIMEOUT_MINUTES` | `60` | A line nobody typed on for this long is hung up |
| `SSH_CHANNELS_PER_CONNECTION` | `8` | Console lines sharing one SSH connection to the jump server; keep it below the jump server's sshd MaxSessions (10 by default) |

## Console journal

| Variable | Default / example | Description |
|---|---|---|
| `JOURNAL_RETENTION_DAYS` | `14` | What the devices printed (never keystrokes), with who held the keyboard; readable by the people who were there, their team and the admins. Read rights cover the whole day of a console: someone on any session of R1 today reads every session of R1 today |
| `JOURNAL_MAX_KB_PER_DAY` | `5120` | Size cap of one device's journal for one day, in KB |
| `JOURNAL_MAX_TOTAL_MB` | `1024` | Size cap of every journal together, in MB: past it, the oldest days go first |
